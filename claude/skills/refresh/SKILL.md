# /refresh

사용자가 자주 쓰는 지시를 1개 명령으로 실행한다:
"로드맵 업데이트하고 병렬처리 가능한거 병렬진행처리 후 미사용 세션 정리하고 결정해야 할 것 알려주고 진행해줘"

승인 규칙은 현재 프로젝트의 CLAUDE.md를 따른다. 무인 진행이 있는 프로젝트(예: 벗)는 확인 없이 진행한다. 없는 프로젝트는 세션을 열기 전에 확인받는다.

멈춤 규칙: 할 일이 남았으면 멈추지 않는다. 일반 오류와 타임아웃은 직접 원인을 찾아 풀고 넘어간다. 의도적으로 막힌 것(접근 거부, 건드리지 말라고 표시된 파일, 안전 장치)만 보고한다. 되돌리기 어려운 작업 전에는 묻는다. 사용자가 "계속해"를 다시 입력할 일이 없게 한다.

## 절차

1. 상태를 읽는다: `HANDOFF*.md` → `ROADMAP.md` → 최근 결정 기록 → `git status`.
2. 연결된 세션을 확인한다: `list_sessions` (`linked: true`). 실행 중인 세션의 결과를 확인한다.
3. `ROADMAP.md`를 고친다. 끝난 단계를 표시하고 다음 단계를 정한다.
4. 다음 단계 중 독립된 일을 고른다. 조건: 다른 일의 결과가 필요 없다. 같은 파일을 고치지 않는다.
5. 독립된 일을 하위 세션으로 연다. 동시 세션 수는 전역 CLAUDE.md의 규칙을 따른다 (기본 3개). 세션마다 모델 · 노력 수준 · 완료 기준을 쓴다. 세션과 서브에이전트는 1개마다 토큰 비용이 새로 붙는다. 병렬로 할 수 있는 일에만 연다. 몇 번의 도구 호출로 끝나는 일은 이 세션에서 한다.
6. 쓰지 않는 세션을 보관한다 (`archive_session`). 삭제가 필요하면 먼저 묻는다. 대상: 끝났고 결과를 확인한 세션. 사용자를 기다리는 세션과 실행 중인 세션은 보관하지 않는다.
7. 결정할 것을 모아 보고한다. 되돌리기 어려우면 `결재:`, 답이 필요한 요청이면 `알림:`, 추천안으로 이미 진행했으면 `확인:`을 앞에 쓴다. 항목마다 추천안 1개와 이유 1줄을 쓴다. 사용자가 그대로 답할 수 있는 행동 문장도 쓴다 (예: "네, `X` 세션을 보관해"). "응, 진행해"처럼 대상이 없는 답은 어느 항목의 승인인지 알 수 없기 때문이다.
8. 결정이 필요 없는 일은 계속 진행한다.

## 보고 양식

첫 두 문장에 찾은 것과 바뀐 것만 쓴다. 코드를 보지 않은 사람이 읽는다고 생각하고 쓴다. 그 다음에 아래 목록을 쓴다.

- 로드맵: 바뀐 단계
- 연 세션: 이름 · 모델 · 노력 수준 · 맡은 일
- 보관한 세션: 이름 · 이유
- 결정할 것: `결재:` / `알림:` 줄
- 계속 진행하는 일
